# 01 — 保留记录边界

**依赖**：无
**标签**：`type:feature` `domain:memory` `risk:high`

## 问题

`ImageAssembler.build()` 把连续记录合成 `Segment` 后，**原文件的行边界就丢了**。
写回时只能按默认字节数重新切分，导致未改动的行也变了 ——
`git diff` 显示整文件改动，改了哪个量看不出来。这是 §6.2 / §6.3 的直接障碍。

## 做

1. `Segment` 增加 `boundaries: tuple[int, ...]` —— 段内各原始记录块的起始偏移（相对段起点，升序，首项恒为 0）。
   语义是格式无关的：「这段由哪些连续记录拼成」。
2. `ImageAssembler.build()` 在合并 chunk 成段的同时累积切分点。
   **不改 `add()` 的签名** —— 每个 `add` 调用即一个记录块，插件一行都不用改。
3. 重叠覆盖时边界的处理要有定义：被完全覆盖的块不产生边界点，部分覆盖按实际落点处理，并在 `warnings` 里说清。

## 不做

- 不引入任何格式名（hex / s19 / record / line 这类词不许出现在 core 里）

## 验收

- 两条连续记录（0x100 起 16 字节、0x110 起 16 字节）→ 合成一段，`boundaries == (0, 16)`
- 三条 → `(0, 16, 32)`
- 不连续的两块 → 两个段，各自 `boundaries == (0,)`
- 单个 chunk 不截断（不按 16 字节自动切）
- 空 `AddressSpace` 不炸
- 重复 `build()` 结果一致
