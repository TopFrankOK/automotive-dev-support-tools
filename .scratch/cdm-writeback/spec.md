# 规格：CDM 无损往返写回

**状态**：已发布
**日期**：2026-10-16
**前序**：P1（标定 CDM 端到端，读已就绪）、P3（软件刷写）

## 1. 一句话

把标定值写回内存镜像文件（HEX / S19），并且**除了被改动的字节，其它一个字节都不变**——
包括文本行的切分方式。

## 2. 为什么它是「硬」的

「写回」听起来像序列化，其实不是。序列化会把镜像重新排版一遍：
行的字节数、段的顺序、基地址记录的位置全变。
结果是 `git diff` 显示整文件改了，改了哪个量、改了多少，**人看不出来**。

标定文件是要进版本库、要过评审的。所以这里的正确性定义比序列化严格得多：

> **未改动的字节必须逐字节相同，且未改动的行必须逐字符相同。**

这一条决定了下面的全部设计。

## 3. 范围

### 做

- 按地址就地改写，不重排、不合并、不填充空洞
- 沿用原文件的记录行边界（`Segment.boundaries`）
- 值 → 原始字节编码（`DataType` + 字节序），与 `CompuMethod.to_raw()` 对齐
- 校验和重算（改了值不更新校验和，刷进 ECU 会被拒）
- 原子写入（已有 `FileSource.write_all()`：tmp + `os.replace`）
- HEX 与 S19 两个 writer 插件
- CLI 写回命令

### 不做

- **不做**重新布局 / 段合并 / 空洞填充
- **不做**二进制镜像（`.bin`）写回：没有记录边界，也没有地址元信息，做了就是猜
- **不做** A2L 描述文件本身的写回（只写值，不改描述）
- **不做** DCM / CDFX 值集写回（那是另一条路，将来再说）

## 4. 接缝在哪

与 P3 同一条原则：**格式知识沉到插件，核心只认识地址与字节**。

```
core    AddressSpace.write(addr, data)   就地改写
        Segment.boundaries               原文件的记录切分点
        iter_blocks()                    按边界产出 (地址, 字节) 块
        _write_characteristic()          标定量 → 字节（格式无关）
        recompute_checksums()            校验和重算
                    ↕  (地址, 字节)
plugins writer-hex / writer-s19          块 → 文本行（含 checksum、基地址记录、EOF）
```

判断标准：**core 里不出现 hex / s19 / intel / motorola 任何一个词**。

## 5. 三条必须守的规则

1. **不猜。** 地址不在镜像内、元素个数未知、数据类型不支持 —— 一律报出来，不写。
   `bind_image()` 已经这么做了（空洞填 0xFF 冒充真实值是标定事故），写回同理。
2. **校验和必须重算。** 这是「改完刷不进去」最常见的根因。
   `ChecksumSpec.store_address` 不在镜像内时**必须报错**，不能 `pass` 吞掉
   （`memory/model.py:285` 现在就是在吞）。
3. **原子写。** 写到一半崩了，原文件不能成半截。已有 `FileSource.write_all()`，直接用。

## 6. 验收标准

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 改一个量的值，其它字节逐字节不变 | parse→改→写→parse，逐字节比对 |
| 2 | 未改动的行逐字符不变（含行尾与行序） | 文本行级比对 |
| 3 | 一行都不改时，输出文件与输入文件**完全相同** | 字节级 `==` |
| 4 | 改了值后校验和随之更新 | 断言校验和地址处的字节变了 |
| 5 | 校验和地址不在镜像内时必须报错 | 构造该情形，断言抛错/告警 |
| 6 | 写坏一半不留半截文件 | 目标不可写时断言失败并保留原文件 |
| 7 | HEX 与 S19 各自往返 | 两个插件各跑一遍 |
| 8 | 依赖契约仍然 4 kept / 0 broken | `lint-imports` |

第 3 条是最容易被漏掉的：它保证「没改动就不动文件」，
这条不过，写回功能就不该被信任。

## 7. 已知待决（按默认推荐定）

| 决策 | 取值 | 理由 |
|---|---|---|
| 记录边界从哪来 | `ImageAssembler` 在合并 chunk 时保留切分点 | 插件调用方式不用改，格式无关 |
| 没有边界信息时怎么办 | 按格式默认切分（HEX 16 字节/行） | 全新镜像也要能写出文件 |
| 超过 0xFFFF 的地址 | writer 负责插入 04（HEX）/ S3（S19）基地址记录 | 属于格式知识 |
| 校验和算法来源 | 内置 sum8/16/32、xor8、crc32；`algorithm_ref` 非空时报错而不是瞎算 | 厂商私有算法算错比不算更糟 |
| 写回哪些量 | 显式给出的值（值集或改动集），不做「全量重写」 | 全量重写 = 重新排版，违反 §6.3 |
